1. 账号凭据

扫码登录最省事：和在新设备上登录一样，手机 B站 App 扫一下就行，全程不碰 Cookie。 不想扫码，也可以整段粘贴 Cookie / cURL，脚本会自己挑出需要的两个值。

用 B站 App 扫描这个二维码。
为什么不能"复制网址"？怎么手动找 Cookie？（点开）
SESSDATA 和 bili_jct 是 HttpOnly Cookie：网页脚本读不到，它们也 永远不会出现在网址里。所以复制地址栏拿不到登录态——这是浏览器安全模型决定的， 不是实现问题。要么扫码，要么从 Cookie 里取。

手动取：
1. 在浏览器里正常登录 bilibili.com
2. 按 F12，切到 Network（网络）
3. 刷新页面，点列表里任意一个请求
4. 右键它 → Copy → Copy as cURL，把整段粘到上面
5. 或找 Request Headers → Cookie 整行复制
粘贴内容里多余的 Cookie 会被丢弃，只保存 SESSDATA 和 bili_jct。

4. 预览与执行

执行必须用预览时生成的一次性令牌。计划变了令牌就变，所以确认的就是你看到的这一份。 两个计划可以同时预览，然后一次性都执行。

先点上面的「预览」。

5. 每天自动跑一次

用 Windows 任务计划程序，不需要留着这个页面或任何进程。

自动运行的三个真实限制：
1. 定时任务无人值守，所以用不了确认令牌——安装这个任务本身就是授权。
2. 它每次会自动重抓快照，否则计划会基于过期数据。
3. Cookie 会过期（通常约一个月）。过期后该次运行会在日志里明确报错， 不会静默什么都不做，但需要你回来重新粘贴凭据。
